# Personal Finance Workbench architecture

## Files

- `app.json`: manifest; no network or tools; DuckDB storage; no schedule.
- `server.ts`: `paise`, CSV and JSON `records`, `normalize`, `load`, `handleAction`, and `view` with `overviewSurface`, `ledgerSurface`, `importSurface`; `surfaceFile()` for `surface.json`.
- `surface.json`: `view({})`, generated by `node scripts/app-surfaces.ts`.

## Flow

```text
field edit → handleAction(bindPath) → month, budget or import draft → load(month) → view
Import → records(text) → ID clash check → INSERT in one transaction → receipt, month = last imported month → load → view (focus Overview)
Delete all → ask_clear → clear_ledger (DELETE FROM ledger) → view
view → 3 updates (nodes + whole data) → registry lints, applies and commits state + database atomically
```

## Data

`load(month)` returns `total`, `months[]`, the month's `rows[]`, `categories[]` (spending by category), `daily[]` (net by date) and `monthly[]` (money in and out for the latest 12 months). Surface data: `/totals`, `/budgetUsed`, `/budgetMax`, `/budgetTone`, `/categories`, `/daily`, `/running`, `/monthly`; `/transactions`; `/receipt`, `/ledgerSize`.

## Boundaries

Each run is a fresh sandbox (30 s) with a bounded DuckDB snapshot stored in the app record. Limits: 50,000 characters per paste, 200 rows per import, 2,000 in the ledger.
