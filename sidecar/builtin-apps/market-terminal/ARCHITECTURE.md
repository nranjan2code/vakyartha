# NSE Market Terminal architecture

## Files

- `app.json`: manifest; brokered network with exactly three NSE read tools; DuckDB storage; an opt-in five-minute `refreshMarket` trigger.
- `server.ts`: `normalize`, `handleAction`, `refreshMarket`, and `view` with `marketSurface`, `instrumentSurface`, `sourcesSurface`; `surfaceFile()` for `surface.json`.
- `source.ts`: decoding and validation of NSE tool output (`quote`, `indices`, `history`).
- `analytics.ts`: the `prices` table, transactional history replacement and the SQL analysis.
- `surface.json`: `view({})`, generated by `node scripts/app-surfaces.ts`.

## Flow

```text
field edit (batched by host) → handleAction(bindPath) → save draft → render
Refresh → validate watchDraft → 3 index reads + quote reads → receipts, problem → render
Open / Fetch → quote + history read → saveHistory (DuckDB transaction) → render (focus Instrument)
render → analyze(prices, symbol) → view(state, analysis) → 3 updates (nodes + whole data)
registry → lint, apply on the previous snapshot, commit state + database + surfaces atomically
```

## Data

State: `watchlist[]`, `watchDraft`, `symbol`, `symbolDraft`, `months`, `quotes{symbol → quote}`, `broad[]`, `sectoral[]`, `derivatives[]`, `receipts[]` (≤ 40), `historyFor{}`, `problem`, `checkedAt`. DuckDB: `prices(symbol, date, open, high, low, close, volume)`, primary key `(symbol, date)`. Surface data is derived per surface: `/headline`, `/watch`, `/moves`, `/sectors`, `/indices`; `/quote`, `/history`, `/sma`, `/returns`, `/stats`; `/receipts`.

## Boundaries

Each run is a fresh sandbox (30 s) reaching NSE only through the governed tool mailbox. The database is a bounded snapshot stored with the app record. Limits: six watchlist symbols, 80 history rows per read, 100 indices per group, 40 receipts.
