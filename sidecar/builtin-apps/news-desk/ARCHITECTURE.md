# News Desk architecture

## Files

- `app.json`: manifest; brokered network with the single `web__fetch_page` tool; no database; an opt-in 15-minute `refresh` trigger.
- `server.ts`: `normalize`, `feed`, `refresh`, `handleAction`, and `view` with `headlinesSurface`, `savedSurface`, `sourcesSurface`; `surfaceFile()` for `surface.json`.
- `feed.ts`: `sourceBody` (the tool's original response), `parseFeed` (RSS, Atom, JSON Feed), `canonical`, `plain`.
- `surface.json`: `view({})`, generated by `node scripts/app-surfaces.ts`.

## Flow

```text
field edit → handleAction(bindPath) → category or new-feed draft → view
Refresh → for each feed: web__fetch_page → sourceBody → parseFeed → merge by canonical URL → receipts, problem → view
Save / Remove / Add feed → change state → view
view → 3 updates (nodes + whole data) → registry lints, applies and commits atomically
```

## Data

State as in AGENTS.md. Surface data is derived: `/articles` (filtered by category) and `/byCategory`, `/byDay` (last 14 publication days), `/byFeed` for coverage; `/saved`; `/feeds`, `/newFeed`, `/receipts`.

## Boundaries

Each run is a fresh sandbox (30 s); feeds are reached only through the governed tool. Responses over 240,000 characters, DTDs, entity declarations and malformed nesting are rejected. Limits as in README.md.
