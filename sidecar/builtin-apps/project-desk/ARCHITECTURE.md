# Project Activity Desk architecture

## Files

- `app.json`: manifest; brokered network with the single `web__fetch_page` tool; no database; an opt-in 15-minute `refresh` trigger.
- `server.ts`: source parsing (`repository`, `source`, `items`, `commits`), `normalize`, `refresh`, `handleAction`, and `view` with `triageSurface`, `activitySurface`, `sourcesSurface`; `surfaceFile()` for `surface.json`.
- `surface.json`: `view({})`, generated by `node scripts/app-surfaces.ts`.

## Flow

```text
repository field → /repoDraft saved → Refresh validates it (a new repository clears the sample)
Refresh → issues, pulls, commits via web__fetch_page → validate → receipts, problem → view
board move → /cards → validated lanes → view
view → 3 updates (nodes + whole data) → registry lints, applies and commits atomically
```

## Data

State as in AGENTS.md. Surface data is derived: `/counts`, `/byState`, `/byLabel`, `/byDay`, `/cards`, `/issues`; `/commitDays`, `/timeline`, `/pulls`; `/receipts`.

## Boundaries

Each run is a fresh sandbox (30 s); the API is reached only through the governed tool. At most 30 records per response; 24 receipts.
