---
name: periodic-report
description: Prepare a daily, weekly or monthly status/performance report from supplied records, prior reports or governed source reads, with an optional dashboard.
---

Resolve exact period boundaries, timezone and the source's reporting basis. Distinguish a complete period from month/week/day to date. Use a prior period only when comparable data exists; identify changed definitions, missing days and different coverage. Do not invent last period's values or summarize a longer window from one snapshot.
Structure around the requested audience and decisions: supported changes, exceptions, unresolved issues and next actions. Preserve source identities and distinguish reported facts from interpretation. For a dashboard load enabled dashboard and interactive-ui when not active; the always-on surface-design guidance applies; for a short text report respect that format. Put a concise finding, period and caveat in visible prose that also works aloud. When the user requests daily, weekly or monthly reporting, clarify whether that is the data window or a delivery request when ambiguous. Creating this report does not create a recurring schedule; saving or sending requires an offered destination and confirmed receipt.
