---
name: surface-design
description: Design visual and spoken canvas content: forms, tables, charts, cards, metrics and mixed layouts. Combine with interactive-ui for data bindings and actions.
---

Design around the person's task and requested outputs. If bindings or submissions are needed, load interactive-ui when enabled and not already active. Use the offered semantic components and props; arbitrary HTML, CSS, scripts and expression strings are not a styling runtime.

Establish a clear title, brief context and a primary content area. Group related fields and results in sections; use cards for meaningful groups, not every label. Put a short metric strip before detail when metrics are requested. Keep status meaning in text as well as tone. Use the app's theme, consistent spacing and restrained accents.

Size for content rather than filling every gap. Use grid with explicit columns for peer panels; use split with ratio for a primary/detail layout only when offered. Use stack for reading order and compact controls. Set common props.maxWidth to sm for compact summaries, md for forms/small charts, lg for detailed views, full for dense tables or deliberately wide content. Grid span controls track occupancy; maxWidth controls content measure. Prefer top alignment for panels of different heights. Allow empty space instead of enlarging a short control or summary to match a long neighbour.

Keep forms labelled, grouped and initialized only from supplied values or explicit defaults; place the main submit action near its fields. Give tables clear units and visible row identities. Choose charts by question: bar for category comparisons; stacked for additive parts across categories; line for ordered time; area for magnitude over ordered time; pie for nonnegative parts of one whole; scatter for paired numeric variables; heatmap for nonnegative intensity by date or matrix; radar for comparable measures on a common scale. Histograms need supplied or checked bins shown as bars. Do not substitute scatter for sized bubbles, or claim candlesticks, box plots, waterfall, dual-axis or statistical overlays are supported. For unsupported types, explain the limit and offer an appropriate supported chart or table. Use calendar/timeline for events and gantt for supplied start/end work only when those components are offered. Before finalizing, check that a chart's plotted categories and series agree with its title, description and nearby interpretation. If it shows only part of the available data, name the selected categories or periods and say where the remaining values appear; do not describe a subset as complete. Avoid decorative or duplicate charts. Name periods, units and missing-data limitations.

Design the spoken projection from the same content and facts. Put the main finding, period and important limitation in short visible text near the start; keep its first sentence meaningful by itself. The conversation gist shortens card bodies and tables, and ordinary reading skips control labels. A warning must not exist only in a card body, tooltip, colour or input. Put units and descriptive labels in content; avoid relying on column position or unexplained symbols. A chart's spoken endpoints are not a complete trend analysis: state any supported interpretation in text. Do not invent a separate tts field or narration store. Preserve the user's language and update summaries when submitted criteria change.

Keep primary content first when columns collapse. Wide tables may scroll inside their panel; forms and ordinary prose must fit narrow containers. Preserve independent surfaces and drafts on revision. Do not claim a layout was visually verified without actual rendering evidence.
